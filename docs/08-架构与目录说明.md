## 三、依赖规则（怎么保证不破层）

| 层 | 允许依赖 | 禁止 |
|---|---|---|
| `app/` | `bsp/*.hpp`（纯虚接口）、`common/`、`modules/` | 任何 `HAL_*`、`CMSIS` 底层寄存器 |
| `modules/` | `bsp/*.hpp`、`common/` | 任何 `HAL_*`、FreeRTOS 以外的东西 |
| `bsp/` | `HAL_*`、`cmsis_os2.h` | 上层具体业务 |
| `common/` | 标准库、`cmsis_os2.h` | 具体外设 |

**怎么检查**：整仓搜索

```powershell
Select-String -Path app\*,modules\*\* -Pattern 'HAL_[A-Z]+\('
```

结果应为空。（注释里提到"不许出现 HAL_"不算。）

## 四、三条主干数据流

### ① CAN 收发（Comm 任务，1 ms 周期）

```
CAN1 FIFO0 中断 → bsp::can1 环形队列（16 帧）
                        ↓
              Comm 任务（1 ms）取帧 → 限速 1 Hz 打印
                        ↓
              每 100 ms 组帧 → bsp::can1.send()
```

**中断只搬数据，不解析**。解析和打印都在任务里做。

### ② 传感器采样（Sensor 任务，5 ms 周期）

```
Sensor 任务 → module::Mpu6050::read_raw()（I2C 阻塞，约 1.3 ms）
                     ↓
             5 ms 采一次，1 Hz 打印一次
```

### ③ 日志（异步）

```
任意任务 → log_impl() → snprintf 到 80 B 栈缓冲 → osMessageQueuePut（永不阻塞）
                                                          ↓
                                    log_task（最低优先级）→ 逐字节发 USART1
```

## 五、关键设计取舍（面试常问的三点）

### 1. 为什么接口用纯虚类而不是函数表

```cpp
class Uart {
 public:
  virtual common::Err write(const uint8_t*, size_t, uint32_t) = 0;
  virtual common::Err write_async(const uint8_t*, size_t) = 0;
};
extern Uart& uart1;
```

好处：
- 上层拿到的是引用，**没有全局状态函数**，便于在测试里替换成假实现
- 编译期就能发现"没实现"（纯虚函数）
- 不需要函数指针表的初始化顺序问题

代价：每个调用多一次虚表跳转（约 2 个周期），在 1 ms 周期的任务里完全可忽略。

### 2. 为什么错误用 enum class 而不是 int

```cpp
enum class Err : uint8_t { Ok, Timeout, Busy, InvalidParam, NotInit,
                           BusError, NoAck, NotFound, Overflow, Unknown };
```

- 强类型，不能和 `int` 隐式互转（避免 `if (ret)` 这类含糊判断）
- `switch` 时编译器能提示漏掉的分支
- 配合 `to_str()` 可以直接打进日志，**现场看到的是 `Timeout` 而不是 `3`**

### 3. 为什么日志要异步

实测一行 33 字节 @115200 需要 **2.9 ms**。若让 1 ms 周期的 Comm 任务直接 printf，
周期立刻变成 3.9 ms——实时性被日志拖死。

异步化后业务任务只花约 0.1 ms（格式化 + 入队），剩下的交给最低优先级任务。
