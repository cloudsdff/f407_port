# 接口说明

> 任务01 要求"清晰接口定义"。本文列出四个公开接口和三个实现，说明每个方法的
> **返回什么、在什么情况下返回什么**——这是"不允许静默失败"的具体落地。

## 一、统一错误码 `common/error_code.hpp`

```cpp
enum class Err : std::uint8_t {
  Ok,            // 成功
  Timeout,       // 超时（通信无响应）
  Busy,          // 忙（上一次操作未完成 / 重复初始化）
  InvalidParam,  // 参数非法（空指针、长度 0、范围外）
  NotInit,       // 未初始化就调用
  BusError,      // 总线错误（I2C 无应答、CAN 发送失败等）
  NoAck,         // 设备无应答（I2C 地址不通）
  NotFound,      // 探测不到设备 / 资源不存在
  Overflow,      // 缓冲区不足
  Unknown
};

const char* to_str(Err e);   // 打进日志用，现场看到的是 Timeout 而不是 3
inline bool ok(Err e) { return e == Err::Ok; }
```

**设计原则**：所有可能失败的函数都返回 `Err`，不返回 `bool`（丢信息）、不返回 `int`（可被忽略）。

## 二、日志 `common/log.hpp`

```cpp
namespace common {
  void log_init();                                    // 建队列 + Log 任务
  void log_impl(LogLevel lv, const char* fmt, ...);   // 实际入口（宏会调它）
  std::uint32_t log_dropped();                        // 被丢弃的条数
  std::uint32_t log_sent();                           // 已成功发送的条数
}

#define LOG_D(...)  // Debug（LOG_LEVEL >= 3 才编译）
#define LOG_I(...)  // Info
#define LOG_W(...)  // Warn
#define LOG_E(...)  // Error（永远编译）
```

| 特性 | 说明 |
|---|---|
| 异步 | 格式化后用 `osMessageQueuePut` 入队，**永不阻塞调用者** |
| 有界 | 队列 12 × 80 字节 = 960 B |
| 可观测 | 队列满时 `logdrop` 计数递增，不是静默丢弃 |
| 内核启动前可用 | `osKernelGetState() != osKernelRunning` 时退化为同步输出 |
| 中断上下文 | 用 `common_log_sync()`（直接写 UART，不碰队列） |

**输出格式**：`[级别][tick] 内容\r\n`，例如 `[I][5016] stats: tx=49 rx=49 ...`

## 三、UART `bsp/uart.hpp`

```cpp
class Uart {
 public:
  virtual common::Err write(const uint8_t* data, size_t len, uint32_t timeout_ms) = 0;
  virtual common::Err write_async(const uint8_t* data, size_t len) = 0;
  virtual common::Err read(uint8_t* data, size_t len, uint32_t timeout_ms) = 0;
  virtual bool is_idle() const = 0;
};
extern Uart& uart1;
```

| 方法 | 方式 | 返回 |
|---|---|---|
| `write` | 阻塞（`HAL_UART_Transmit`） | `Ok` / `Timeout` / `BusError` |
| `write_async` | **DMA**（`HAL_UART_Transmit_DMA`） | `Ok` / `Busy` / `Overflow` / `NotInit` / `InvalidParam` |
| `read` | 阻塞 | `Ok` / `Timeout` |
| `is_idle` | 查询 | `true` = 上一帧已发完 |

**失败场景与返回值**

| 情况 | 返回 |
|---|---|
| `data == nullptr` 或 `len == 0` | `InvalidParam` |
| `len > 256`（内部缓冲上限） | `Overflow`（不截断发送） |
| 上一帧还没发完就再调 `write_async` | `Busy`（不覆盖） |
| 驱动里没配 DMA（`hdmatx == nullptr`） | `NotInit` |
| 底层 HAL 返回错误 | `BusError` |

**实测**：256 字节 × 100 帧 = 25600 字节零错位，带宽利用率 96.5%（见 docs/02）。

## 四、I2C `bsp/i2c.hpp`

```cpp
class I2c {
 public:
  virtual common::Err write_reg(uint8_t dev, uint8_t reg, const uint8_t* data,
                                size_t len, uint32_t timeout_ms) = 0;   // 阻塞
  virtual common::Err read_reg(uint8_t dev, uint8_t reg, uint8_t* data,
                               size_t len, uint32_t timeout_ms) = 0;    // 阻塞
  virtual common::Err read_reg_async(uint8_t dev, uint8_t reg, uint8_t* data,
                                     size_t len) = 0;                    // 中断
  virtual bool busy() const = 0;
  virtual common::Err probe(uint8_t dev, uint32_t timeout_ms) = 0;
  virtual common::Err recover_bus() = 0;
};
extern I2c& i2c1;
```

| 方法 | 说明 |
|---|---|
| `probe` | 发地址看有没有应答。**读任何寄存器之前必须先探一次**，否则设备不在时会读回 0xFF 被当数据用 |
| `recover_bus` | F103 I2C1 的 errata：从机把 SDA 拉死时，DeInit → SCL 打 9 个时钟 → 重新 Init |
| `read_reg_async` | `HAL_I2C_Mem_Read_IT`，完成后置标志，调用方用 `busy()` 判断 |

**实测**：拔 SDA 后 1 秒内检测到，自动恢复耗时 **4 ms**，插回数据即恢复（docs/03）。

## 五、CAN `bsp/can.hpp`

```cpp
struct CanFrame {
  uint32_t id;
  uint8_t  len;
  uint8_t  data[8];
};

class Can {
 public:
  virtual common::Err start(uint32_t accept_std_id = 0xFFFFFFFFu) = 0;
  virtual common::Err send(const CanFrame& f, uint32_t timeout_ms) = 0;
  virtual common::Err recv(CanFrame& f, uint32_t timeout_ms) = 0;
  virtual uint32_t tx_count() const = 0;
  virtual uint32_t rx_count() const = 0;
  virtual uint32_t rx_dropped() const = 0;
  virtual uint32_t error_count() const = 0;
  virtual uint32_t busoff_count() const = 0;
  virtual bool need_recovery() const = 0;
  virtual common::Err recover() = 0;
};
extern Can& can1;
```

| 方法 | 说明 |
|---|---|
| `start(id)` | 配过滤器（只放行 `id`，`0xFFFFFFFF` = 全通）+ 启动 + 打开 FIFO0/错误中断 |
| `send` | 阻塞入邮箱。邮箱满时最多等 `timeout_ms`，超时返回 `Timeout` |
| `recv` | 从环形队列取帧，队列空返回 `Timeout` |
| `need_recovery` | 是否进过 bus-off（控制��自己停摆，必须重启） |
| `recover` | `HAL_CAN_Stop` + `Start`，恢复计数 +1 |

**为什么 CAN 没有 DMA**：bxCAN 的发送是"3 级邮箱"机制，写进去后硬件自己仲裁和重发，CPU 不参与搬运，硬件上不存在 CAN-DMA 通道。

**实测**：F103 ↔ F407 跨型号互通，单向 1800+ 帧，`drop=0 err=0`（docs/04、docs/07）。

## 六、MPU6050 `modules/mpu6050/mpu6050.hpp`

```cpp
class Mpu6050 {
 public:
  enum Reg : uint8_t { kRegPwrMgmt1 = 0x6B, kRegWhoAmI = 0x75, ... };
  static constexpr uint8_t kAddrDefault = 0x68;
  static constexpr uint8_t kWhoAmIValue = 0x68;

  struct Raw {
    int16_t ax, ay, az;   // ±2g 量程，1g = 16384 LSB
    int16_t temp;         // 需要 temp/340 + 36.53 换算
    int16_t gx, gy, gz;   // ±2000dps 量程，1dps = 16.4 LSB
  };

  explicit Mpu6050(bsp::I2c& bus, uint8_t addr = kAddrDefault);
  common::Err init();                  // 探测 + 校验 WHO_AM_I + 唤醒 + 设量程
  common::Err read_raw(Raw& out);      // 阻塞读 14 字节
  common::Err read_raw_async(Raw& out);// 中断读
  bool busy() const;
  bool inited() const;
};
```

**`init()` 的四道关**（少一道都会出错）

1. `probe(0x68)` —— 地址上有没有人应答
2. 读 `WHO_AM_I`（0x75）必须是 **0x68**
3. 写 `PWR_MGMT_1`（0x6B）= **0x00** —— 不唤醒的话六轴数据全是 0
4. 设量程：`ACCEL_CONFIG = 0x00`（±2g）、`GYRO_CONFIG = 0x18`（±2000dps）

**实测偏差**：静止时加速度模长 **1.119 g**（理想 1.000 g），说明这颗廉价模块有 +12% 的零偏/标度误差。
这正是任务02"上电自校准和零漂抑制"要解决的问题（docs/03）。

## 七、返回值使用规范（本项目内部约定）

```cpp
// 1. 初始化类：失败就上报 + 降级，不阻断其他任务
Err e = mpu_.init();
if (e != Err::Ok) {
  LOG_E("mpu init -> %s", to_str(e));
  (void)i2c1.recover_bus();      // 尝试恢复一次
}

// 2. 周期读：失败只记一次，避免刷屏
if (r != Err::Ok) {
  if (++lost == 1) { LOG_W("mpu read lost (%s)", to_str(r)); }
}

// 3. 发送类：失败计数 + 继续下一轮，绝不 while(1)
if (can1.send(f, 20) != Err::Ok) { /* 统计里体现 */ }
```

**三条硬规则**

1. 任何阻塞调用都要有 timeout
2. 错误必须带上下文（错误码 + 关键寄存器）
3. 能自动恢复的必须自动恢复
