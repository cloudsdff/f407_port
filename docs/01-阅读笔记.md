# 读 basic_framework 串口部分的笔记

读的是湖南大学跃鹿战队开源的 basic_framework，仓库在 D:\stm32\basic_framework_ref。

花了两小时，主要看 `bsp/usart` 这一块。原因是任务一要求封装串口，而这是现成的参考实现，先把别人怎么做的搞明白，再想自己怎么写。

## 先把目录过了一遍

`application/` 是业务，真正的入口是 `robot.c`，里面有个 `RobotInit()`，用一个宏（ONE_BOARD、CHASSIS_BOARD 这些）决定这块板子要初始化哪些子系统。所以同一份代码可以编出云台板、底盘板、单板三种固件。

`bsp/` 是板级，把芯片的串口、CAN、I2C、SPI、PWM、ADC 各自包一层。里面没有业务代码，找不到"云台""底盘"这种词。

`modules/` 是器件级，imu、motor、oled、remote、referee 这些，一个器件一个目录。每个器件自己知道怎么跟 bsp 打交道。

`Drivers/` 是 CubeMX 生成的 ST HAL 库，没人改它。`Middlewares/` 放 FreeRTOS。`Inc/` 和 `Src/` 也是 CubeMX 的产物，跟 `Core/` 一个性质。

根目录同时有 CMakeLists.txt 和 Makefile，这个工程两套构建都给了。

## 串口这条线是怎么走的

初始化阶段是这样的：

```
main()
  RobotInit()                    application/robot.c
    __disable_irq()              先把中断关了
    BSPInit()                    bsp/bsp_init.h，只初始化 DWT 和日志
    RobotCMDInit()               模块在这一步注册串口
    OSTaskInit()                 建任务
    __enable_irq()               再开中断
```

我一开始不明白为什么要在初始化时关中断。想了一下大概能懂：初始化过程中对象还没建好，这时来个串口中断，回调里找不到实例，就会出问题。先把中断关掉，等所有东西都建好了再开，是稳的做法。

运行起来以后，数据是这么进来的：

```
串口收到数据
  DMA 往 instance->recv_buff 里搬（CPU 不参与）
  收满或者总线空闲，触发中断
  HAL_UARTEx_RxEventCallback()    bsp_usart.c:102
    拿 huart 指针去名册里比对，找到是哪个实例
    调 instance->module_callback()   模块自己的解析函数
    清缓冲
    重新开一次 DMA 接收
```

中间那句"重新开一次 DMA 接收"很关键。HAL 的 DMA 接收只干一次，收完就停，不重新调用的话只能收到第一包，后面就静悄悄没了。

## 三个地方的对应关系

注册的时候，模块把自己的解析函数交给 bsp，bsp 存进一个静态数组。之后中断来了，bsp 靠串口句柄在数组里找到实例，再调那个函数。

所以 bsp 根本不认识"遥控器"或者"视觉"这些模块，它只知道"这个串口后面挂了一个函数"。模块也不需要知道串口怎么配。两边靠一个函数指针连起来，这就是所谓的解耦。

名册是个静态数组，最多三个实例，`idx` 记已经用了几个。串口是点对点独占的，所以不需要 id，一个句柄对应一个模块。

## 没看懂、记下来待查的

`gState` 具体哪几位是什么意思。HAL 里这个字段存串口状态，READY、BUSY_TX、BUSY_RX 一大堆，注释里没写全。

IDLE 中断到底是什么时候触发。大概理解成"总线上一段时间没有新数据"，用它来判断一帧结束，但具体阈值是多少还没查。

弱函数 `__weak` 的机制。CubeMX 生成的 HAL 里到处是这个，意思是用户重写同名函数就能覆盖库里的实现。串口回调能被我自己写一遍，靠的就是这个。

DWT 是什么。看来是 Cortex-M 内核里的周期计数器，能用来做微秒级延时。

daemon 这个东西。看起来是模块里的守护机制，负责检测设备掉线和重连，具体怎么实现的没看。

## 几点感受

原来分层不是把文件分到不同文件夹里，是规定谁能看见谁。application 只 include module 的头文件，module 只 include bsp 的，bsp 才 include HAL。这样上层换芯片的时候基本不用动。

原来回调是为了让底层能反过来调用上层。bsp 是被 module 调用的，但数据来了又得由 bsp 去调 module，只能靠函数指针。

接收缓冲是注册时就定好大小的固定数组，不是要用的时候才申请。这个直接影响 RAM，一个实例就是 256 字节，三个就快 800 了。我这块板子只有 20K，得算着用。

还有一点，整个框架的中文注释写得挺清楚，很多地方直接写了"这是 HAL 库的设计失误"。作者知道自己绕的是什么，这种注释比"本函数用于……"有用多了。
