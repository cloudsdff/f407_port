# 演示视频脚本

> 目标时长 **7–8 分钟** · 建议 1080p、录屏 + 手机拍板子结合
> 录制顺序建议：**先录屏（3 段），后拍板子（2 段）**，最后剪辑拼接

## 一、拍摄前准备清单（按此顺序摆好，能省很多重录）

| # | 准备项 | 说明 |
|---|---|---|
| 1 | 两块板都上电 | F103（蓝药丸）+ F407（黑卡板）都插 USB |
| 2 | 两个串口窗口都打开 | **两个 SSCOM 实例**，一个 COM7（F103），一个 F407 的 COM 口，都 115200 |
| 3 | 两个窗口分别改名 | 标题写清 "F103 (A: 0x123)" / "F407 (B: 0x456)" |
| 4 | CAN 总线接好 | 两个 TJA1050 的 CANH-CANH、CANL-CANL、两板共地 |
| 5 | MPU6050 接在 F103 上 | 视频里要演示"拔掉它不影响系统" |
| 6 | 编辑器打开 `app/app_main.cpp` | 后面要展示分层 |
| 7 | 终端进入 `D:\stm32\f103_w1` | 后面要跑 grep 和 git log |

## 二、分镜脚本

### 镜头 1：开场（0:00–0:35）

**画面**：桌面全景 —— 两块板、两个 TJA1050、杜邦线、MPU6050。

**说**：
> 这是我做的任务01 框架。两块 STM32，一块 F103、一块 F407，
> 通过 500 kbps 的 CAN 总线对发数据。整个框架分三层：应用层、模块层、BSP 层。

**必须拍到**：两块板都亮着灯，CAN 线连着。

---

### 镜头 2：先给结论 —— 已完成的要求（0:35–1:10）

**画面**：切到 `docs/08-架构与目录说明.md`，滚动展示分层图。

**说**：
> 考核有五项要求：分层、FreeRTOS 任务划分、每个外设两种访问方式、
> 统一错误码和日志、移植到不同型号。这五项我都做了，而且每一项都有实测数据。
> 这个视频按顺序演一遍。

---

### 镜头 3：分层是怎么保证的（1:10–2:20）

**画面**：终端，执行：

```powershell
Select-String -Path app\*,modules\mpu6050\* -Pattern 'HAL_[A-Z]+\('
```

**结果为空**。

**说**：
> 应用层和模块层搜不到任何 HAL 调用。HAL 只出现在 `bsp/bsp_*.cpp` 这三个文件里。
> 这就是为什么后来移植到 F407 时，业务代码一行都不用改。

**接着**：打开 `app/app_main.cpp`，滚动到 `comm_task`。

**说**：
> 应用层看到的是 `bsp::can1.recv()`、`bsp::can1.send()` 这样的接口，
> 完全不知道底层是 HAL 还是寄存器。

---

### 镜头 4：启动与时钟（2:20–3:00）

**画面**：F407 的串口窗口，先按复位，然后**立刻**（趁 banner 输出前）看数据：

```
===== F407 port boot =====
SYSCLK=168000000 HCLK=168000000 PCLK1=42000000 PCLK2=84000000
[I][10] app layer ready (C++17, HAL-free)
[I][10] can: started (filter id=0x123, FIFO0 irq on)
```

**说**：
> 这行 `PCLK1=42000000` 是 CAN 能不能跑 500 kbps 的关键。
> F103 的 PCLK1 是 36 MHz，F407 是 42 MHz，所以两边的 CAN 分频器不一样——
> 移植时我在这里踩过坑。

> ⚠️ **串口必须在复位前就打开**，否则 banner 会丢

---

### 镜头 5：任务在跑（3:00–3:50）

**画面**：F103 串口窗口，等 5 秒出现：

```
[I][5016]  stats: tx=49 rx=49 drop=0 err=0 busoff=0 logsent=21 logdrop=0
[I][5016]  stack free: Comm=352 Sensor=360
[I][10017] stats: tx=99 rx=99 drop=0 err=0 busoff=0 logsent=37 logdrop=0
```

**说**：
> 五个任务：Comm 1 毫秒周期管 CAN、Sensor 5 毫秒采传感器、
> Log 任务优先级最低负责发日志、还有 LED 心跳和栈水线观察。

> `stack free` 是实测的剩余栈空间，Comm 剩 352 字节、Sensor 剩 360 字节，
> 都在安全线上。`logdrop=0` 说明异步日志队列没溢出。

**必须拍到**：`stack free` 和 `logdrop=0` 这两项。

---

### 镜头 6：CAN 双板互通（3:50–5:00）★ 重点镜头

**画面**：两个串口窗口并排（左 F103，右 F407）。

两边同时滚动：

```
F103: [I][xxxx] rx id=0x456 len=8 seq=...
F407: [I][xxxx] rx id=0x123 len=8 seq=...
```

**说**：
> 左边 F103 发 0x123、收 0x456；右边 F407 发 0x456、收 0x123。
> 两边都在收对方的帧，seq 一直在涨，err 是 0。

> 注意这是**跨芯片型号**：F103 是 Cortex-M3，F407 是 Cortex-M4F。
> 同一份业务代码，只改了 BSP 层的三行句柄名，就能互通。

**必须拍到**：两个窗口同时出现 `rx`，且 ID 互为对方。

**加一个细节镜头**：把 F407 断电 3 秒再上电，F103 侧出现：

```
[W][xxxx] can send failed: Timeout
```

**说**：
> 对端断电时，发送不会卡死，而是按超时返回错误码。这就是"不允许静默失败"。

---

### 镜头 7：失败路径（5:00–6:40）★ 加分镜头

#### 7a. 拔 MPU6050（5:00–5:50）

**画面**：手机拍板子，拔掉 MPU6050 的 VCC，然后看 F103 串口：

```
[W][353985] mpu lost, recovery...
[W][353988] i2c: bus recovery start
[W][353992] i2c: recover done, re-init Ok
[W][355047] mpu lost, recovery...
```

**说**：
> I2C 掉线被立刻检测到，自动执行恢复：DeInit、在 SCL 上打 9 个时钟、重新 Init，
> 全过程 4 毫秒。而且 CAN 完全没受影响——**一个传感器坏了不影响整个系统**。

#### 7b. 插回去（5:50–6:10）

插回 SDA/VCC，数据自动恢复：

```
[I][356060] acc[-1460,1928,19356] gyro[-218,-83,0]
```

**说**：
> 不需要按复位键，插回去数据就恢复了。

#### 7c. 日志队列灌满（6:10–6:40，可选）

**画面**：展示 `docs/06-失败路径矩阵.md` 里的证据：

```
[I][10016] stats: tx=99 rx=99 drop=0 err=0 busoff=0 logsent=47 logdrop=30
```

**说**：
> 日志队列满了会丢日志，但 CAN 的收发一帧不丢，而且丢了多少会算出来告诉上层。

---

### 镜头 8：移植总结（6:40–7:30）

**画面**：`docs/07-移植说明.md`，滚动到"改动清单"。

**说**：
> 从 F103 移植到 F407，实际只改了三个文件：
> `bsp_can.cpp` 里把 `hcan` 改成 `hcan1`，两行；
> `main.c` 里加三处 USER CODE；
> 还有 CMakeLists 加一个用户编译块。

> 应用层、模块层、日志、错误码，**一行都没动**。

> 另外 CubeMX 里有两处必须改：CAN 的位时序（因为 PCLK1 从 36 变 42 MHz），
> 还有 F4 把 CAN 错误中断拆成了独立的 `CAN1_SCE`——不勾这一项，
> 硬件在报错但软件永远看不到。

## 三、录制技巧

| 问题 | 解决 |
|---|---|
| banner 丢了 | **先开串口，再按复位键** |
| 日志滚太快看不清 | 串口工具里取消"自动清屏"，缩小字号让更多行可见 |
| 两个窗口不好同屏 | 用 OBS 或 Windows 游戏栏录全屏，两个窗口左右平铺 |
| 板子特写虚焦 | 手机拍照时手肘撑桌面，或把板子垫高 |
| 讲解卡壳 | **先按脚本念一遍再开录**，或者后期配音 |

## 四、必须出现在成片里的 6 个数字

| # | 数字 | 出处 |
|---|---|---|
| 1 | `PCLK1=42000000` | F407 启动横幅 |
| 2 | `logdrop=0` | F103 stats |
| 3 | `stack free: Comm=352 Sensor=360` | F103 stats |
| 4 | 两个窗口的 `rx id=0x456` / `rx id=0x123` 同时出现 | 双板互通 |
| 5 | `i2c: recover done` 出现后数据恢复 | 拔插 MPU6050 |
| 6 | `can send failed: Timeout` 且系统继续跑 | F407 断电 |
