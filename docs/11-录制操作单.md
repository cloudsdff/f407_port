# 录制操作单（照着一步步做）

> 用途：录视频时放在手机或另一块屏幕上照着念
> 总时长目标：7–8 分钟 · 建议**分段录**，每段录完按停止，出错了只重录那一段

---

## 第 1 段：双板互通（约 2 分钟）★ 最重要

### 动作

1. **点开始录屏**
2. 鼠标移到 F407 板子的 USB-C 线，**拔掉**
3. 数 2 秒，**插回去**
4. 等两个窗口滚起来，停 3 秒不说话（让观众看数据）
5. 停止录屏（这一段可以单独录，不用一条过）

### 会看到

**右窗（COM7 / F407）**：

```
===== F407 port boot =====
SYSCLK=168000000 HCLK=168000000 PCLK1=42000000 PCLK2=84000000
[I][10] app layer ready (C++17, HAL-free)
[I][10] can: started (filter id=0x123, FIFO0 irq on)
[I][10] can start -> Ok (accept id=0x123)
```

**左窗（COM6 / F103）**，在 F407 断电那 2 秒里：

```
[W][xxxxx] can send failed: Timeout
```

### 说什么（分两段录，可分别补）

**① 断电瞬间（指着左窗）**

> 现在我把 F407 断电。注意左边 F103 的反应——它不会卡死，而是按超时返回错误码。

**② 恢复后（指着两个窗口）**

> 右窗是 F407，发 0x456、收 0x123；左窗是 F103，发 0x123、收 0x456。
> 两边都在收对方的帧，`drop=0`、`err=0`、`logdrop=0`。
> 一个是 Cortex-M3，一个是 Cortex-M4F，在 500k 的 CAN 上双向互发。

### 必须拍到

- `PCLK1=42000000`
- 左窗 `rx id=0x456`
- 右窗 `rx id=0x123`
- 右窗 `stats: ... drop=0 err=0 busoff=0 logdrop=0`

## 第 2 段：任务与栈水线（约 1 分钟）

### 动作

1. 开始录屏
2. 指着右窗的 `stats:` 和 `stack free:` 两行
3. 等它们再刷一次（5 秒一轮）
4. 停止

### 会看到

```
[I][xxxxx] stats: tx=.. rx=.. drop=0 err=0 busoff=0 logsent=.. logdrop=0
[I][xxxxx] stack free: Comm=336 Sensor=336
```

### 说什么（三句）

> 这个框架一共五个任务：Comm 1 毫秒周期管 CAN，Sensor 5 毫秒采传感器，
> 日志任务优先级最低，负责把日志慢慢发出去。

> `stack free` 是实测的剩余栈空间，Comm 剩 336 字节、Sensor 剩 336 字节，都在安全线以上。

> `logdrop=0` 说明异步日志的队列没溢出——日志是丢在队列里、由低优先级任务发的，不会阻塞业务。

## 第 3 段：失败路径（约 2 分钟）★ 加分

### 动作

1. 开始录屏（手机拍板子 + 屏幕都可以，建议屏幕为主）
2. 指着左窗，等 `acc[...]` 那一行
3. **拔掉 MPU6050 的 VCC 线**
4. 等 3 秒
5. **插回去**
6. 等 5 秒
7. 停止

### 会看到

```
[W][xxxxx] mpu lost, recovery...
[W][xxxxx] i2c: bus recovery start
[W][xxxxx] i2c: recover done, re-init Ok
...
[I][xxxxx] acc[-1460,1928,19356] gyro[-218,-83,0]     ← 插回后自动恢复
```

### 说什么（三句）

> 我现在把传感器拔掉。一秒内被检测到，然后自动执行 I²C 总线恢复：
> DeInit、在 SCL 上打 9 个时钟、重新 Init，整个过程 4 毫秒。

> 注意这段时间里 CAN 完全没受影响——**一个传感器坏了不影响整个系统**。

> 现在插回去，不用按复位键，数据自己就恢复了。

### 必须拍到

- `mpu lost, recovery...`
- `i2c: recover done`
- 插回后的 `acc[...]`

## 第 4 段：分层证据（约 1 分钟）

### 动作

1. 开始录屏
2. 切到 VS Code，终端里依次跑：

```
cd D:\stm32\f103_w1; (Get-ChildItem app,modules -Recurse -Include *.cpp,*.hpp | Select-String 'HAL_[A-Z]' | Measure-Object).Count
```

**输出 `0`**（停 2 秒）

```
cd D:\stm32\f103_w1; (Get-ChildItem bsp -Recurse -Include *.cpp | Select-String 'HAL_[A-Z]' | Measure-Object).Count
```

**输出 `57`**（停 2 秒）

```
cd D:\stm32\f103_w1; & "C:\Users\Lenovo\Tools\PortableGit\cmd\git.exe" log --oneline
```

**输出 16 行**（停 2 秒）

3. 停止

### 说什么（三句）

> 先证明分层是真的。在应用层和模块层搜 `HAL_`，结果是 0。

> 同样的搜索放到 bsp 层，57 条。也就是说 HAL 调用不是没有，而是全被关在 bsp 那一层。

> 这是提交历史，16 次提交，从最小工程、FreeRTOS、三层骨架、三个外设、六条失败路径，一直到移植。

### 必须拍到

- 那个 `0`
- 那个 `57`
- `git log` 的 16 行

## 第 5 段：移植（约 1 分半）

### 动作

1. 开始录屏
2. 切到 `docs\07-移植说明.md`，按 `Ctrl+Shift+V` 开预览
3. 滚到 **「二、实际改动清单（6 处）」**
4. 滚到 **位时序对比表**（`Prescaler 4 → 6`）
5. 停止

### 说什么（五句）

> 这一部分是移植。先说结论：**业务代码一行没改**。

> 从 F103 换到 F407，真正动的只有三个文件：`bsp_can.cpp` 把 `hcan` 改成 `hcan1`，两行；
> `main.c` 加三处 USER CODE；`CMakeLists` 加一个 C++ 编译块。

> 但是 CubeMX 里有两处必须改。第一是 CAN 的位时序——F103 的总线时钟 36 兆，
> F407 是 42 兆，同样 4 分频就不是 500k 了，必须改成 6 分频、BS1 11、BS2 2。

> 第二是中断向量。F1 把 CAN 中断合在一个里面，F4 拆成四条，错误中断走独立的 `CAN1_SCE`。
> 我一开始只勾了 RX0，结果是寄存器里发送错误计数器已经 128，日志里 `err` 还是 0——硬件在报错，软件看不见。

> 分层的价值不是看起来整齐，而是换芯片的时候，你不用重新理解整个项目。

## 翻车应急

| 情况 | 处理 |
|---|---|
| banner 没拍到 | 重录第 1 段：**先开串口，再拔 USB-C 插回** |
| SSCOM 串口打不开 | 检查是不是被别的程序占着（关掉多余的 SSCOM） |
| 命令输出不对 | 先单独跑 `cd D:\stm32\f103_w1`，再跑命令 |
| J-Link 掉线（COM7 消失） | 停录，拔插 J-Link USB，等 COM7 回来，重录当前段 |
| 板子没响应 | 拔插 USB 供电，等 10 秒 |
| 录制时长超了 | 优先删第 6 段（片头片尾），核心是第 1、3、4、5 段 |
