# 移植说明：STM32F103C8T6 → STM32F407VET6

> 日期：2026-11-21 · 工程：`D:\stm32\f407_port`（源工程 `D:\stm32\f103_w1`）
> 结论：**业务代码零改动**，只改了 3 个文件、共 6 处。

## 一、两块板的关键差异

| | STM32F103C8T6 | STM32F407VET6 |
|---|---|---|
| 内核 | Cortex-M3（无 FPU） | Cortex-M4F（有 FPU） |
| 主频 | 72 MHz | 168 MHz |
| **PCLK1（CAN/I2C 挂这条）** | **36 MHz** | **42 MHz** |
| PCLK2（USART1 挂这条） | 72 MHz | 84 MHz |
| Flash / RAM | 64 KB / 20 KB | 512 KB / 128 KB |
| CAN 外设 | bxCAN，**14** 个筛选器组 | bxCAN，**28** 个筛选器组 |
| CAN 中断 | **1 个合并中断**（`USB_LP_CAN1_RX0`） | **拆成 4 个**（TX / RX0 / RX1 / **SCE**） |
| HAL 句柄名 | `hcan` | **`hcan1`** |
| HAL 时基定时器 | TIM4（F1 无 TIM6/7） | **TIM6** |

## 二、实际改动清单（6 处）

### 1. `bsp/bsp_can.cpp`：句柄改名（3 处）

```diff
-extern CAN_HandleTypeDef hcan;
+extern CAN_HandleTypeDef hcan1;   // F4 的 HAL 里句柄叫 hcan1（F1 叫 hcan）

-CAN_HandleTypeDef* const kCan = &hcan;
+CAN_HandleTypeDef* const kCan = &hcan1;

-if (hcan_h == &hcan)
+if (hcan_h == &hcan1)
```

**`bsp_uart.cpp` 和 `bsp_i2c.cpp` 一行没改**——因为 F1/F4 的 HAL 里 `huart1` / `hi2c1` 命名一致。

### 2. `CMakeLists.txt`：追加用户层编译单元

新增 C++17 支持、7 个源文件、5 个头文件目录、编译选项。
内容与 F103 工程的用户块**完全一致**（只是 `CMAKE_PROJECT_NAME` 由 CubeMX 生成）。

### 3. `Core/Src/main.c`：三个 USER CODE 块（3 处）

```c
/* USER CODE BEGIN Includes */
#include <stdio.h>
/* USER CODE END Includes */
```

```c
/* USER CODE BEGIN 2 */
printf("\r\n===== F407 port boot =====\r\n");
printf("SYSCLK=%lu HCLK=%lu PCLK1=%lu PCLK2=%lu\r\n", ...);
extern void app_init(void);
app_init();
/* USER CODE END 2 */
```

```c
/* USER CODE BEGIN 4 */
extern int bsp_uart1_putchar(int ch);
int __io_putchar(int ch) { return bsp_uart1_putchar(ch); }
extern void common_log_info(const char* fmt, ...);
/* USER CODE END 4 */
```

### 4. CubeMX 侧：CAN 位时序必须重算

F1 的 PCLK1 是 36 MHz，F4 是 42 MHz，**同样的分频器得不到同样的波特率**：

| 参数 | F103 | **F407** |
|---|---|---|
| Prescaler | 4 | **6** |
| Time Quanta in BS1 | 15 | **11** |
| Time Quanta in BS2 | 2 | **2** |
| ReSynchronization Jump Width | 1 | 1 |
| 总位数 | 18 TQ | **14 TQ** |
| 采样点 | 88.9% | **85.7%** |
| 校验 | 36÷4÷18 = 500k | **42÷6÷14 = 500k** |

### 5. CubeMX 侧：HAL 时基换成 TIM6

F1 没有 TIM6/TIM7，用的是 TIM4。F4 有 TIM6，选它做 HAL 时基，SysTick 留给 FreeRTOS。

### 6. CubeMX 侧：**必须勾上 `CAN1_SCE interrupt`**

这是移植中最容易漏、也最难查的一处：

| | F103 | F407 |
|---|---|---|
| 错误中断走哪 | 合并在 `USB_LP_CAN1_RX0` 里 | **独立的 `CAN1_SCE_IRQn`**（SCE = Status Change Error） |

只勾 `CAN1_RX0` 的后果：**收帧正常，但错误永远进不来**，`err` 计数恒为 0。

实测证据（当时 F103 断电，F407 一直在 ACK 错误）：

```
MSR: INAK=0 SLAK=0 RX=1              ← 总线隐性，收发器有电
ESR: TEC=128 REC=0 LEC=3 BOFF=0      ← LEC=3 = ACK 错误，TEC 已到 error-passive 阈值
TSR: TME0-2=7                        ← 三个邮箱全空（帧发完就被丢弃）
RF0R: FMP=0                          ← 一帧都没收到
```

而我们的日志里 `err=0`——**硬件在报错，软件看不见**。
补勾 `CAN1_SCE` 后立刻变成 `err=2`，错误可见了。

## 三、验证结果

### 启动横幅（时钟树正确）

```
===== F407 port boot =====
SYSCLK=168000000 HCLK=168000000 PCLK1=42000000 PCLK2=84000000
[I][10] app layer ready (C++17, HAL-free)
[I][10] can: started (filter id=0x123, FIFO0 irq on)
[I][10] can start -> Ok (accept id=0x123)
```

`PCLK1=42000000` 是关键——CAN 的 500 kbps 依赖它。

### 跨型号 CAN 互通（F103 ↔ F407）

F407（B 节点，发 `0x456`、收 `0x123`）串口输出：

```
[I][177848] rx id=0x123 len=8 seq=2447
[I][178848] rx id=0x123 len=8 seq=2457
[I][179948] rx id=0x123 len=8 seq=2468
[I][180014] stats: tx=1800 rx=221 drop=0 err=2 busoff=0 logsent=101 logdrop=0
```

- `rx id=0x123`：收到的是 F103 发的帧（F407 自己是 0x456）
- 帧间隔 1000 ms（日志限速每秒一条，实际收发是 100 ms 一帧）
- `err=2` 是 F103 断电期间累计的 ACK 错误，之后不再增长
- `drop=0` `logdrop=0`：两个队列都没溢出

### 资源占用对比

| | F103C8T6 | F407VET6 |
|---|---|---|
| Flash | 54 KB / 64 KB（**83%**） | 57 KB / 512 KB（**11%**） |
| RAM | 16.6 KB / 20 KB（**81%**） | 16.7 KB / 128 KB（**13%**） |

**同一份业务代码，在 F103 上紧张到要算每个字节，在 F407 上完全不是问题。**

## 四、为什么能"一次编译通过"

分层架构的实际收益：

| 层 | 移植时改动 |
|---|---|
| `app/`（应用层） | **0 行** |
| `modules/`（模块层） | **0 行** |
| `common/`（错误码/日志） | **0 行** |
| `bsp/bsp_uart.cpp` | **0 行** |
| `bsp/bsp_i2c.cpp` | **0 行** |
| `bsp/bsp_can.cpp` | **3 行**（句柄改名） |
| `main.c` | **3 处 USER CODE** |
| `CMakeLists.txt` | 1 个用户块 |

**这就是"业务代码不依赖 HAL"的真正价值：换芯片只换一层皮。**

反例：如果按照参考框架的写法（模块层直接调 `HAL_I2C_*`、中断里调模块函数），
移植时要改的是**所有模块文件**，而且每改一处都可能引入新 bug。

## 五、F407 上的待办

- LED：F407 板载 LED 引脚与本项目不同，当前移植版没配 LED（验证靠串口 + CAN）
- MPU6050：F407 板上没接传感器，日志里如实报 `probe failed (NoAck)`
  —— 这也验证了"传感器缺失不影响系统"（见 docs/06-失败路径矩阵.md 路径 4）
- 可以把 F407 的 FPU 打开（`-mfpu=fpv4-sp-d16 -mfloat-abi=hard`），当前用软浮点，对现有功能无影响
